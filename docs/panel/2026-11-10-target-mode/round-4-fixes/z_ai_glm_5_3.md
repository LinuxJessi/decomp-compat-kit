# z-ai/glm-5.3

## 1. The round-2 fixes

1. **Register-based pairing degrades to positional pairing when the register check fails — this is a real wrong-addend vector.** In `_pair_by_offset`, `noff = (same or cands)[0]`: if the `lui` register is copied (`addu $v0,$at,$zero; addiu $v0,$v0,%lo`) or re-loaded before the `%lo`, the LO16's rs is not the HI16's rt, `same` is empty, and the first positional candidate is used — which may belong to a *different* `lui` and a different object. The same fallback exists in `_section_lo_shared` (`or his`) and harvest_relocs (`or his`). A wrong addend usually produces a mismatch (fail-safe), but if it lands in an `_anchored` span whose content matches the original (e.g. zero-filled .bss, duplicated string data), the wrong object is proven and a false MATCH is possible. **Confirm/refute:** construct a self-test with `lui $at,%hi(A); addu $v0,$at,$zero; addiu $v0,$v0,%lo(B); lui $at,%hi(A2); addiu $at,$at,%lo(A2)` and check which LO16 the HI16 pairs with; and audit whether `_anchored` can succeed for the wrong span when contents coincide.

2. **Pairing is forward-only and function-bounded: `%lo` before `%hi`, or `%lo` past the function end, is unpairable — and the failure is silently reported as a gap, not a forced difference.** `_pair_by_offset` requires `off < noff < hi_f`. A `%lo` in the first instructions of the *next* function (its `%hi` in the preceding function's delay slot — normal inter-block scheduling around `jr`/branch delay slots) falls outside `hi_f` and returns `None`, which `_section_hi` reports as "HI16 without paired LO16". This is almost certainly your 2 unverifiable functions. Fail-safe direction, but see finding 3 for whether the failure path is fully safe.

3. **The unpaired-HI16 path does not force a difference on the HI16.** When `_section_hi` returns the "without paired LO16" message for `.rodata` (outside the `startswith(("jump table entry", "HI16/LO16 outside"))` prefixes and outside anchor mode or before anchoring), the HI16 word is left *unrelocated* and merely recorded in `unresolved`. If the driver treats "unresolved" as "skip this reference but keep comparing", the HI16 field compares the assembler's raw addend against the original — which can match by luck (small .rodata offsets are common values). Round 2 flagged "a failed proof did not force a difference on the %hi"; the fix only covers the `_anchored`/"content" and jump-table paths, not the no-pair path. **Confirm/refute:** check the driver's handling of `unresolved` entries; if the word is masked rather than forced, a small-offset HI16 can match incidentally.

4. **`_rodata_table_va` trusts the original's 16-bit fields without checking they are a `lui`/`addiu` pair at those sites.** It reads `_image_word(hi_va)`/`(lo_va)` regardless of what instruction the original actually holds there. If the original has different instruction placement at those offsets, `table` is garbage, and the walk `while addend + 4*n in entries` compares our entry targets against original bytes at a garbage address. It fails open only downward (n==0 → "not a jump table"); with n≥1 and coincidental byte equality it can anchor a wrong address. **Confirm/refute:** add a check that `(orig_hi >> 26) == 0x0F` (LUI) and the LO16 site's opcode uses rs == HI16's rt; add a self-test with scrambled original bytes at the site.

5. **`_relocated_pointers` fixes are incomplete for pointers into `.rodata` strings.** Named symbols and `.text`-relative R_MIPS_32 pointers are now compared (`expect != got` → content mismatch — good, this closes the round-2 masking hole), but a section-symbol R_MIPS_32 into `.rodata` whose addend falls inside an unnamed string still yields `expect = None` and is *masked without comparison*. That pointer can point anywhere in the original without detection. **Confirm/refute:** grep the 353-TU target for R_MIPS_32 relocations against `.rodata` section symbols whose addend resolves to no named symbol; if any exist, the 1985/1985 figure includes functions with unverified string pointers.

6. **R_MIPS_32 addend convention looks correct for REL, but there is no RELA guard.** The addend is read in-place from the section word — right for the REL objects ee-as produces. If a RELA section (sh_type SHT_RELA, r_addend in the reloc entry) ever appears, `struct.unpack_from(E+"I", self._raw, rel["off"]+k*8)` misparses entries and pointers are silently mis-read. **Confirm/refute:** assert `s["typ"] == SHT_REL` (not just `!= SHT_RELA` absence) wherever r_addend-less parsing is used.

7. **`_anchored` is truncated in the review material at `if masked >= end - start:`** — the policy that decides what happens when *every* word of a span is an unresolvable pointer is not reviewable. If it returns success there, a span of all-masked pointers proves nothing and can match anything. **Confirm/refute:** supply the tail; check that `masked == end - start` forces a failure/diff.

8. **$gp range check exists only on the anchors path.** The named-symbol `R_MIPS_GPREL16` range check is gated on `self.anchors is not None`; on the non-anchor path the offset is written unclamped and a >16-bit displacement silently wraps into a matching-looking field. If target mode always has anchors this is inert, but the same code serves the other lane. Also `R_MIPS_LITERAL` is range-checked against `gp`, though the literal pool base is `gp − 0x8000` by convention — off by the pool offset, which can reject valid literals. **Confirm/refute:** find a LITERAL relocation in the targets and check the computed field against the retail word.

9. **The ledger row↔TU fix is sound** (tier keyed on `(tu, name, va, size)`, `tu_of_row` per row), and the atomic `os.replace` write is sound. The `sys.exit(main())+sys.exit(main())` blobs in the diffs are join artifacts, not code — confirm the actual files.

10. **@cflags is now gated by `CFLAG_OK` and the shell risk is closed** (no `/`, spaces, quotes, `;`, `|`, `$`, or `--` survive the pattern). One line: sound.

11. **Branch/jump exclusion in `immediate_only`/`classify_port` is now correct** (opcodes 0x01–0x07, 0x14–0x17 cover REGIMM, beq/bne, blez/bgtz and the -likely forms), and unknown relocation types now count as differences in `masked_compare`. Sound. Residual: `addi/addiu/lui/ori` immediates may still differ freely by design — confirm that is the intended contract, not an oversight.

## 2. The two unverifiable ".rodata HI16 without paired LO16" functions

The two remaining patterns ee-gcc 2.96 produces that defeat forward, function-bounded pairing:

- **`%hi` in the delay slot of a function's final branch, `%lo` as the first instruction of the next function** (or vice versa, `%lo` in the last delay slot with `%hi` at the top of the fallthrough target): inter-block scheduling moves one half of the pair across the FUNC boundary, and `_func_of` excludes it.
- **`%lo` before `%hi` in address order**: GCC 2.96 basic-block reordering / loop rotation can place the `addiu %lo`-bearing block below its `lui %hi`.

**Confirm/refute:** disassemble the two functions (the report names them) and check which of the two shapes it is; also that the `%lo`'s rs equals the `%hi`'s rt.

**How to pair:** make pairing direction-agnostic and register-driven: for a HI16 with rt=R, scan the enclosing function *and* the adjacent function's first/last two instructions (delay-slot window) for a LO16 against the same symbol with rs==R, in either address order; accept the pair only if exactly one such candidate exists, otherwise force a difference on both fields (finding 3). The register check, not instruction order, is the invariant the ABI actually guarantees at run time.

## 3. upstream_target.py

12. **Cross-unit name collisions resolve to one address — a silent wrong-symbol-address, and a false-MATCH vector in verify.** Every CSV row is written `bind=GLOBAL`, and `add()` dedupes on `(binary, name)` only, but verify looks symbols up by bare name (`self.syms.value(sym["name"])`). Two units (or two TUs' statics) that define the same data label name produce two CSV rows and one effective resolution; if the winner's object has content matching what the TU expects, `_anchored` proves the wrong address. C statics (`static int flags;` in two files) make this likely, not exotic. **Confirm/refute:** `sort symbols CSV | uniq -d` on name; check whether `syms.value` scopes by binary or annotation `@addr`.

13. **Functions listed in `<unit>.txt` but absent from `estimated-functions.json` are silently dropped when the unit has any estimated functions.** The condition `if va in own[u] or (size and not own[u])` means a real upstream rename not yet reflected in the estimate disappears with no warning; the function then verifies as "unknown symbol". **Confirm/refute:** diff the `type:func` name set of each `.txt` against the estimate's function list and count orphans.

14. **Data labels outside both the unit's and the resident image are dropped with no warning** (`owner` returns None → the label is never added), and non-ELF originals make `segments()` return `[]`, so *all* data labels vanish silently while the tool still exits 0. Same for a `PROVIDE` whose address is not in the resident image. **Confirm/refute:** run with a deliberately wrong `--game-dir` and compare row counts — only the missing-directory case warns.

15. **`driver_flags` silently pairs a cc1 with the wrong assembler's contract.** `best = best or c` accepts the first contract matching the compiler alone when the assembler doesn't match, so `cc1_flags` (codegen flags) can come from a contract that was never validated for that pair. Wrong flags → systematic mismatches (or, worse, accidentally passing ones) with no diagnostic. **Confirm/refute:** assert exact (compiler, assembler) match or warn.

16. **`contracts` is keyed by `f"{profile}+{as_key}"`, so two distinct tool pairs with the same profile/assembler-key names silently overwrite** — the second TU group compiles with the first contract. **Confirm/refute:** check the upstream's profile names for reuse across toolchains.

17. **Only the resident `_gp` is written; overlays with their own gp are unresolved or resolved against the wrong gp.** `reginfo_gp` is read from `units["main"]`'s original only. In verify this feeds `_site_va`/`_anchored` gp sites for overlay TUs — wrong base gives wrong site addresses. Mostly fail-safe (forced diffs), but it means overlay GPREL references can never anchor and the "8/8 identical" overlay-2 result should state whether any gp-relative reference exists there. **Confirm/refute:** read `.reginfo` from each overlay original and compare.

18. **TU drops are silent on schema drift.** `for ... if isinstance(m.get("tus"), dict) else []` turns a list-shaped `tus` into zero TUs, and every filter (`language != "c"`, missing `id`/`path`, missing tool path) drops without a per-TU record — the output only counts what survived, so a manifest with 300 of 353 TUs looks fine. **Confirm/refute:** compare the manifest's `tus` count against the upstream's own build list; add a printed expected-vs-emitted count per unit.

19. **`shndx=1` is hardcoded for every FUNC/OBJECT row** while the upstream's estimates carry a real shndx (used for FUNCs from `own[u]` only). If the consumer ever uses CSV shndx to pick a section, data labels land in the wrong one. **Confirm/refute:** check whether verify_decomp consumes the CSV shndx at all; if not, drop the column's pretense.

20. **Minor:** `reginfo_gp`/`segments` don't guard `shoff == 0` / `phoff == 0` (SHT_NOBITS/ET_EXEC edge cases) and would raise rather than warn; `labels[u].setdefault` lets `.txt` labels silently shadow `data-names.json` names; `-G` is stripped from assembler options while the docstring claims "-G stays per-TU flags" — confirm ee-as doesn't need it.
